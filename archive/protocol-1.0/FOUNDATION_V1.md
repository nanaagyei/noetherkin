# Foundation V1

Status: specification complete, implementation not started. Protocol version: 1.0.

This document and the nine versioned JSON Schemas establish the V1 protocol. The linked architecture documents, catalogs and contracts are normative parts of this foundation. Examples are illustrative fixture data. MUST, MUST NOT and MAY express requirements, prohibitions and options.

Read [SPEC.md](SPEC.md) for the index. Authority order within this repository is the project charter and explicit user scope, this foundation and its normative documents, then examples. JSON Schema governs structural validity; architecture governs semantic validity. A conflict between these authorities is a defect requiring a documented architecture change proposal, never permission to silently select convenient behavior.

V1 uses inspectable local files, one learner and one selected project per workspace, with historical tasks retained across project switches. Roles describe authority; skills perform bounded workflows under an identified principal. A skill name does not grant authority. The learner authors source by default. Formal judgments cite attributable evidence. E0 is an initial administrative placement, not demonstrated capability. Promotions are immutable, authorized review decisions; summaries cannot grant them.

No runtime, initializer, lifecycle engine, adapters or final skill packages are delivered in this phase. Specification conformance scenarios are not proof that an implementation exists.

Changes to enum meanings, field meanings, role ownership, progression rules or lifecycle gates require a proposal containing the contradiction, alternatives, migration impact, updated schema/catalog versions and conformance cases. Preserve V1 files when a successor is adopted; the `1.0` segment in schema identifiers is immutable. IDs use a reserved `.example` namespace and resolve from the local schema set, never require network access.
