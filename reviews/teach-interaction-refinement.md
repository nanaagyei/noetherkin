# Teach interaction refinement: one offer, then honor the request

Status: user-approved interaction behavior, implemented and observed passing in three corrected Codex repetitions and three corrected Claude repetitions. The earlier variable failure remains preserved. This is not a promotion, schema, assistance-level or permission change.

The accepted eval plan defines the narrow situation: an explicitly marked learning assignment, no attempt, and a first request for its complete solution. The first response offers a graduated route briefly, while leaving direct help available. If the learner repeats the request or declines that route, the skill supplies direct help, attributes the assistance actually given and asks one comprehension question. It does not require an attempt, shame the learner, or restart gates. Already attempted, blocked or urgent authorized work receives no extra offer.

The frozen [assistance model](../docs/architecture/assistance-model.md) permits escalation after an “attempt, a clear blocker, explicit request or urgent authorized work.” The [teach contract](../contracts/teach.md) requires direct-help attribution and a comprehension check and prohibits automatically providing the full solution. Neither requires immediate full implementation on the first unattempted-assignment request or permits indefinite gatekeeping. The entrypoint refinement selects a bounded interaction within those rules; it does not redefine a protocol invariant. No normative contradiction was found, so no architecture change proposal or protocol version change was adopted.

A01 checks both turns as a single interaction. S07 preserves minimal conceptual hints and S08 preserves direct help after attempts. The first corrected Codex batch passed twice and failed once by giving the solution on turn 1; that failure is preserved in attempt 04. After the entrypoint placed the one-off offer before the general explicit-request escalation rule, attempts 05 and 06 passed all three repetitions on Codex and Claude respectively. The expectations were unchanged. The historical raw transcripts are intentionally excluded from version control; the behavioral expectations remain encoded in the executable suite.
